# GitLab Merge Request 描述生成助手

## 任务目标

读取最近 **$1** 个 commit 的提交记录，基于实际变更内容，按照 `.gitlab/merge_request_templates/default.md` 模板格式，生成一份完整的 MR 描述。

---

## 执行步骤

### 第一步：分析变更
1. 读取最近 $1 个 commit 的详细信息（commit message、diff 内容）
2. 识别涉及的模块、文件、功能点
3. 归纳变更类型与核心目的

### 第二步：生成内容
1. 读取模板文件 `.gitlab/merge_request_templates/default.md`
2. 严格按照模板结构逐项填写
3. 将生成结果写入 `tmp/mr_description.md`

---

## 强制规则

### 1. 数据来源约束
- ✅ **只能**基于最近 $1 个 commit 的实际代码变更
- ❌ **禁止**编造、推测或添加未发生的改动
- ❌ **禁止**引用 commit 范围之外的任何变更

### 2. MR 标题格式（必须严格遵守）

```
[模块] type: 简要描述
```

| 字段 | 规则 | 可选值 |
|------|------|--------|
| 模块 | 根据变更涉及的实际模块填写 | `kmc` / `meta` / `kac` / `all` / 多模块用逗号分隔 |
| type | 根据变更性质选择 | `feat` / `fix` / `refactor` / `perf` / `doc` / `style` / `test` / `chore` |
| 简要描述 | 一句话中文概括变更核心 | 不超过 50 字 |

**type 选择指南：**
- `feat`: 新功能
- `fix`: 缺陷修复
- `refactor`: 代码重构（不改变功能）
- `perf`: 性能优化
- `doc`: 文档变更
- `style`: 代码格式调整（不影响逻辑）
- `test`: 测试相关
- `chore`: 构建、依赖、配置等杂项

**正确示例：**
```
[kmc] fix: 修复任务调度重复执行问题
[meta, kac] feat: 新增用户行为统计能力
[all] refactor: 统一错误码定义规范
```

**错误示例：**
```
fix: 修复问题          ← 缺少模块
[kmc] 修复BUG          ← 缺少 type
[KMC] Fix: xxx         ← 大小写错误
```

### 3. 输出要求
- 输出文件路径：`tmp/`
- 你需要重新命名你的输出文档，确保其不包含:等非法字符，可以再各个操作系统中显示、读取
- 文件编码：UTF-8
- 只输出 MR 描述内容本身，不包含任何额外解释

### 4. 内容风格
- ✅ 技术导向，面向代码评审者
- ✅ 客观陈述变更行为、影响范围、风险点、测试情况
- ✅ 语言简洁专业
- ❌ 禁止出现："作为AI"、"根据您的要求"、"我将" 等提示词痕迹
- ❌ 禁止输出与 MR 无关的解释性文字

### 5. 边界情况处理
| 情况 | 处理方式 |
|------|---------|
| commit 数量不足 $1 个 | 基于实际存在的 commit 数量生成，并在描述中注明 |
| 模板文件不存在 | 报错提示，不生成内容 |
| commit 内容为空或无实质变更 | 报错提示，不生成内容 |
| 涉及多种 type（如既有 feat 又有 fix） | 选择主要变更类型，次要变更在描述中说明 |

---

## 输出检查清单

生成完成前，确认以下各项：

- [ ] 标题格式符合 `[模块] type: 描述` 规范
- [ ] 所有内容均来自实际 commit，无编造
- [ ] 模板各必填项均已填写
- [ ] 无提示词痕迹或多余解释
- [ ] 文件已正确写入 `tmp/`
