# 🧪 自动测试最近一个commit $1待测 $2测试文件地址 

## 🎯 目标
根据最近一次 Git commit 的代码修改内容（重点关注 `$1` 表示的路径），自动推断测试需求，并在 `$2` 对应的测试文件中补充或新增测试代码，遵守 CLAUDE.md 中的测试规范，使用 AAA 准则，保持项目现有测试风格，不运行测试，最后提交 git。

---

## 🚀 执行流程

### 1. 读取最近一次 commit
- 读取最近 1 个 commit 的 diff。
- 只关注 `$1` 路径下的代码修改。
- 分析所有新增、修改、删除或重构的代码片段。
- 识别变更可能引入的测试点，包括：
  - 新增函数
  - 新逻辑分支
  - 新增参数或返回值变化
  - 错误处理路径
  - 边界情况
  - 依赖变化或新行为

---

## 📝 2. 分析测试需求

根据修改内容识别：
- 哪些逻辑需要新增测试
- 哪些旧测试未覆盖变更部分
- 哪些边界/异常行为必须补测
- 哪些功能需要回归测试

若 `$2` 下已有测试文件：

### ❌ 禁止
- 修改已有测试 code
- 删除任何已有逻辑
- 重写已有测试

### ✔️ 必须
- **仅追加**新的测试用例
- 保持原测试文件的代码风格、命名方式和格式

---

## 📚 3. 遵循 CLAUDE.md 测试规范

所有测试必须遵循以下要求：

### ✔️ AAA（Arrange – Act – Assert）
每个测试包括：

1. **Arrange**：构造输入、依赖和场景  
2. **Act**：执行被测试函数  
3. **Assert**：断言返回值、状态、行为是否符合期待  

### ✔️ 项目测试风格
- 与现有测试框架一致（例如 Jest / pytest / unittest / vitest）
- 命名清晰、行为导向
- 避免魔法值（magic numbers）
- 异步测试遵从项目模式（如 async/await）

---

## 🏗️ 4. 编写测试文件

### 如果 `$2` 指向的测试文件不存在：
- 创建新测试文件
- 文件名、目录结构按项目规范生成
- 编写所有测试用例
- 结构清晰，包含必要 import

### 如果测试文件存在：
- 阅读现有测试
- 分析未覆盖逻辑
- 追加新的测试，不影响原内容
- 保持一致的风格与结构

---

## 🚫 5. 不得执行测试

- 你只能编写测试，不运行
- 不输出覆盖率
- 不做实际 mock 执行，除非测试需要

---

## 🧾 6. Git 提交

生成测试后，执行：

```bash
git add .
git commit -m "test($1): add tests for latest changes"
```
